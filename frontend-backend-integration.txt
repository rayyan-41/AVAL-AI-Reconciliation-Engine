1. Executive Summary
This document provides a precise, phase-by-phase plan for wiring the AVAL AIRE JavaFX frontend to
its Java backend. All eight UI screens are implemented and validated. This plan details exactly which
service methods each controller must call, what data must be passed through MainUIContext, what
new DataStore methods are required, how background threading must be structured, and what gaps in
the current backend must be filled before integration can proceed.

The backend consists of three services (IngestionService, ReconciliationService, ReportService), two
engine strategies (RuleBasedMatchingEngine, SemanticMatchingEngine), one anomaly engine, and a
single JDBC DataStore backed by PostgreSQL 16 with pgvector. The vectorization layer uses a local
Ollama instance running the nomic-embed-text model.

Phase 6 — Reconciliation Workspace (ReconController)
The most complex integration phase. Three sub-steps: ledger ingestion, bank ingestion, and running the matching
pipeline.

5.5 Threading Rule (applies to all three sub-steps)
All IngestionService and ReconciliationService calls involve file I/O, database writes, and AI model
calls. They must never run on the JavaFX Application Thread. Every backend call must be wrapped in
a JavaFX Task<T>, with UI updates pushed back via Platform.runLater().

5.7 Ledger Ingestion (startLedgerIngestion)
private void startLedgerIngestion(File f) {
    ledgerStatus.setText("Loading...");
    ledgerStatus.getStyleClass().setAll("badge", "badge-pending");

    Task<List<StandardizedTransaction>> task = new Task<>() {
        @Override protected List<StandardizedTransaction> call() throws Exception {
            MainUIContext ctx = MainUIContext.getInstance();
            IngestionService svc = ctx.getIngestionService();
            UUID wsId = ctx.getActiveWorkspace().getWorkspaceId();

            FinancialDataset dataset =
                svc.ingestFile(wsId, f.getPath(), DataSourceType.INTERNAL_EXCEL);
            return svc.standardize(dataset);
        }
    };

    task.setOnSucceeded(e -> Platform.runLater(() -> {
        List<StandardizedTransaction> stdLedger = task.getValue();
        MainUIContext.getInstance().setStandardizedLedgerTransactions(stdLedger);
        ledgerStatus.setText("Loaded — " + stdLedger.size() + " records");
        ledgerStatus.getStyleClass().setAll("badge", "badge-active");
        // Populate ledgerTable with stdLedger
        ledgerTable.setItems(FXCollections.observableArrayList(stdLedger));
        updateReconButtonState();
    }));

    task.setOnFailed(e -> Platform.runLater(() -> {
        ledgerStatus.setText("Error");
        ledgerStatus.getStyleClass().setAll("badge", "badge-review");
    }));

    new Thread(task).start();
}

private void finishReconciliation() {
    Task<List<MatchHypothesis>> task = new Task<>() {
        @Override protected List<MatchHypothesis> call() throws Exception {
            MainUIContext ctx = MainUIContext.getInstance();
            ReconciliationService svc = ctx.getReconciliationService();
            ReconciliationWorkspace ws  = ctx.getActiveWorkspace();
            List<StandardizedTransaction> stdLedger =
                ctx.getStandardizedLedgerTransactions();
            List<StandardizedTransaction> stdBank =
                ctx.getStandardizedBankTransactions();

            return svc.runMatching(ws, stdLedger, stdBank);
        }
    };

    task.setOnSucceeded(e -> Platform.runLater(() -> {
        List<MatchHypothesis> all = task.getValue();
        MainUIContext ctx = MainUIContext.getInstance();
        ctx.setAllHypotheses(all);

        // Split by status
        long autoCount = all.stream()
            .filter(h -> h.getStatus() == HypothesisStatus.AUTO_RECONCILED).count();
        List<MatchHypothesis> pending = all.stream()
            .filter(h -> h.getStatus() == HypothesisStatus.PENDING_REVIEW)
            .collect(Collectors.toList());
        ctx.setPendingHypotheses(pending);

        // Compute unmatched transactions
        Set<UUID> matchedLedgerIds = all.stream()
            .map(h -> h.getLedgerTransaction().getTransactionId())
            .collect(Collectors.toSet());
        Set<UUID> matchedBankIds = all.stream()
            .map(h -> h.getBankTransaction().getTransactionId())
            .collect(Collectors.toSet());
        List<StandardizedTransaction> unmatchedLedger =
            ctx.getStandardizedLedgerTransactions().stream()
               .filter(t -> !matchedLedgerIds.contains(t.getTransactionId()))
               .collect(Collectors.toList());
        List<StandardizedTransaction> unmatchedBank =
            ctx.getStandardizedBankTransactions().stream()
               .filter(t -> !matchedBankIds.contains(t.getTransactionId()))
               .collect(Collectors.toList());
        ctx.setUnmatchedLedger(unmatchedLedger);
        ctx.setUnmatchedBank(unmatchedBank);

        showFeedback("Error: " + task.getException().getMessage())));

    new Thread(task).start();
}

6. Matching Engine Selection Strategy
The ReconciliationService accepts any MatchingEngine implementation. Two engines exist:

Engine Characteristics
RuleBasedMatchingEngine Deterministic. Matches on exact amount + date within 7-day
window. No Ollama dependency. Fast. Produces only
EXACT_RULE hypotheses. Confidence is always 1.0.
SemanticMatchingEngine Uses pgvector ANN search on pre-computed embeddings.
Finds non-obvious matches (narrative similarity). Requires
Ollama and populated embedding columns. Produces
AI_PROBABILISTIC hypotheses with scores 0–1.

Recommendation: Inject RuleBasedMatchingEngine for the first integration milestone. This avoids the
Ollama dependency during matching (embeddings are still generated at ingestion time via
IngestionService.standardize()). Switch to SemanticMatchingEngine in a second pass once
embeddings are confirmed to be persisting correctly in standardized_ledger and standardized_bank.

 Composing both engines
To run both engines, implement a CompositeMatchingEngine wrapper that calls
RuleBasedMatchingEngine first, then SemanticMatchingEngine on the unmatched remainder. This
is not in scope for the initial integration milestone but is the recommended long-term architecture.

Gap Notes
No password / passkey enforcement system_user table has no password column. Auth is identity-
only. Add a password_hash column and bcrypt comparison in a
future sprint.
Email to Company (UC12) handleEmail() is a stub. Needs an EmailService
implementation — SMTP or a third-party API. Not in scope for
the current milestone.
Finance history table from DB getReconciliationHistoryForOrg() returns strings. A structured
HistoryRow query is needed for the typed TableView. Deferred
to second pass.
Workspace status on exit handleExit() does not yet call
DataStore.updateWorkspaceStatus(COMPLETED). Add this
call before navigating back to Registry.
Composite matching engine Running RuleBased + Semantic in sequence for maximum
match coverage. Deferred until embedding persistence is
confirmed correct.
Vectorization progress feedback IngestionService.standardize() may take 2–4 minutes for large
datasets. A progress callback or streaming update mechanism
is not yet implemented.
Multi-session safety MainUIContext is a singleton and is not cleared on exit. If the
user exits and re-enters a different workspace in the same JVM
session, stale lists may persist. Add explicit clearing in
handleExit().
Error recovery in ingestion If standardize() fails midway (Ollama timeout), the partially-
written standardized_ledger rows are not rolled back. A
transaction wrapper or retry mechanism is needed.
